openapi: 3.0.3
info:
  title: CubeFS master — Sync subsystem API
  version: "1.0.0"
  description: |
    P2-cutover HTTP surface for the sync subsystem. The master is the
    authoritative store for sync rules; the cron scheduler runs on the
    raft leader and dispatches tasks across the syncnode fleet via
    OpSyncNodeRunTask packets.

    Endpoints grouped:
      - syncRule  : rule CRUD + state transitions + synchronous trigger
      - syncTask  : task observability + lifecycle (cancel / retry / export)
      - syncNode  : node registration, listing, decommission, drain, restore

    All endpoints share:
      - Auth: requireSyncAdminToken middleware (Bearer <token> or
        X-Sync-Token; empty token disables auth — dev/test default).
      - Envelope: proto.HTTPReply `{code, msg, data}` (code is int32).
      - Error codes:
          0     — success
          1     — InternalError (wraps "not found", "already exists",
                  cycle, generic)
          2     — ParamError (missing field, invalid shardingStrategy)
          4     — PersistenceByRaft (HTTP 503; client retries)
          1014  — duplicate rule pair
          1015  — prefix overlap
          1016  — sync cycle
      - Raft commit failures return HTTP 503 + code=4.

    Wire JSON shape note: SyncRule create/update accepts a FLAT
    SyncRuleConfig body (id, type, src, dst, ...). The server wraps it
    into a SyncRule with `state=active` + server-controlled timestamps
    and lastRun fields.

    name: CubeFS Sync Team
